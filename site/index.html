DEVELOPER SETTINGS

Connect your Sandbox

This prototype only supports PayPal Sandbox. It starts with PayPal's documented sb test shortcut—no invented credentials.

A Client ID is a public app identifier, not a password. Never enter a Client Secret, live credential, card number or API key here. Kept in memory only; resets on refresh.

For production, order creation and capture must move to a secure server. This client-only flow is a Sandbox learning prototype.

BUILT WITH INTENT

Real tools. Honest boundaries.

AI, without an API key

Tesseract.js runs a trained OCR model in a Web Worker on your device. The first scan downloads the engine and English model from a CDN. Receipt images are not uploaded by this app. OCR can make mistakes—always review the numbers.

PayPal is part of the core flow

PayPal JavaScript SDK v5 creates and captures each selected person's test order. The interface records a payment only after PayPal returns a completed capture. It uses the official Sandbox shortcut by default; your own Sandbox Client ID gives you merchant-attributed testing.

What this prototype does not do

No real-money payments, automatic refunds, multiparty payouts, email collection, backend database or cross-device synchronization. A paid share is session-only, and the app locks the bill after a completed capture to prevent changing a paid obligation. This is not production-ready; production needs server-side order validation, authentication, idempotency and verified webhooks.

Precise math, not AI guesses

All money is calculated in integer cents. Shared items, tax and tip use largest-remainder allocation so the shares always reconcile to the bill total. Payment amounts come from this calculation—not OCR confidence or an AI-generated total.
